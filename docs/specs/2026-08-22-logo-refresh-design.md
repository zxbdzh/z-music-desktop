# z-music-desktop 独立品牌 Logo 设计

日期：2026-08-22
状态：设计已批准，待精修母版复核

## 目标

用独立品牌标志替换现有绿色“音符 + 下载箭头”图形，使 `z-music-desktop` 在 GitHub、README、Windows、macOS、Linux 和 Android 上保持一致，同时避免继续沿用上游视觉身份。

成功标准：

- 第一眼稳定识别为单个 `Z`，第二层才读到音乐/音频含义。
- 16×16 像素时仍保留清晰的 Z 主轮廓。
- 适合方形应用图标和 GitHub 圆形头像裁切安全区。
- 不依赖文字、阴影、渐变或细碎纹理建立识别。
- 桌面与 Android 使用同一母版语义，不出现平台间品牌分叉。

## 已比较方向

1. **Z 音频脉冲**：品牌字母与声音语义最强，但第一版上下折返成双 Z/闪电，波形抢占焦点。
2. **唱片轨道**：圆形裁切与音乐库语义较好，但 Z 品牌含义过于隐晦。
3. **桌面声窗**：产品定位最直观，但更像通用品类图标，品牌独占性较弱。

选择方向 1，并将其修正为“单一显性 Z 内嵌声波”。

## 正式视觉规范

### 核心标记

- 画布中心只出现一个完整、粗壮的几何 `Z`。
- Z 使用珊瑚红 `#FF3F5F`，横画与斜画保持一致的视觉重量。
- Z 的端部采用适度圆角，避免尖锐闪电感。
- 禁止上下双 Z、重复折返或额外的字母形状。
- 禁止使用文字排版来绘制 Z；Z 必须是独立几何标记。

### 音频语义

- 在 Z 的斜向中段以背景负空间镂出一条短、简洁、对称或近似对称的声波。
- 声波只作为第二层细节，不切断 Z 的整体阅读。
- 16px 允许声波弱化或不可见；32px 以上应能读到声波。
- 不再使用两侧大型均衡柱、普通音符、耳机、麦克风、下载箭头或单独播放三角形。

### 色彩与背景

- 主色：`#FF3F5F`。
- 中性色：`#171A1C`，只允许用于必要的小面积校准，不作为第二主体。
- 辅助色 `#3E6BE0` 不进入正式核心标记，避免三色造成小尺寸噪声。
- 母版使用暖白纯色背景，派生平台资产时按平台要求提供透明背景或 adaptive icon 背景。
- 禁止渐变、阴影、3D、玻璃拟态、摄影、半调纹理和复杂背景。

### 几何与安全区

- 母版为 1024×1024 PNG。
- 标记占画布约 64%–70%，四周保留至少 15% 安全区。
- 在圆形裁切内不得切掉 Z 的横画端部。
- 最细有效部分不得小于画布宽度的约 6%。
- 灰度显示时仍须保持完整轮廓。

## 资产更新范围

实施分支必须从新独立仓库 `origin/main` 建立，不得把旧功能分支历史重新引入。

### 仓库与 README

- 保存可复现的精修提示词与品牌母版。
- 替换 `doc/images/icon.png`，保持 README 当前相对路径可用。

GitHub 仓库没有独立头像字段；本需求中的“仓库 Logo”定义为仓库内品牌资产及 GitHub Social Preview。

### Android

- 更新 `ic_launcher_brand.xml` 的几何标记为同一单 Z 语义。
- 保留 Android adaptive icon 的 safe zone、背景资源和现有 Manifest 引用。
- 必要时同步 mipmap launcher PNG、foreground 与 round 变体，使旧设备和 adaptive icon 路径一致。
- Splash 品牌图仅在其当前含义与 launcher 标记一致时同步更新，不改变启动页布局。

## 生成与派生流程

1. 使用 `relay-imagegen`、`gpt-image-2`、1024×1024、PNG、high 生成一张精修母版候选。
2. 只做文件存在性、格式、尺寸、响应 JSON 和 SHA-256 技术校验；不自动重生成或自动审美评分。
3. 用户看过并接受母版后，才将其派生为仓库和平台资产。
4. 派生过程只允许裁切、缩放、透明度处理和格式转换；不得用程序覆盖或重画生成图中的核心标记。
5. 若母版不符合视觉要求，必须由用户再次授权后才能额外调用中转站。
